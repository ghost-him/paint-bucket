# celclean — 把 AI 出的赛璐璐图「洗干净」

AI 画图（GPT / 即梦 / Midjourney …）产出的赛璐璐（平涂）风格图，放大看总有一层**脏脏的云雾噪点**：
本来该是一块纯色的地方，布满了云状斑块和颗粒，怎么调都像被压缩过。对平涂风格来说这是硬伤。

celclean 做的是**按色块重画**：

1. 把颗粒和云雾斑块从纯色区抹掉（每个像素用周围颜色相近的像素的平均值替换）；
2. **保住**腮红、头发阴影这类真实渐变，以及 1–2 像素的细线、线稿、边缘抗锯齿；
3. 顺手把 alpha 通道也收拾干净（内部 253 → 255、背景杂点清零）。

它不做放大、不改画风、不移动线条——只把「不干净的底色」变成「干净的底色」。

## 二、安装

需要 [uv](https://docs.astral.sh/uv/)（一个 Python 包管理器，装一次就行）。

```bash
# 在本目录下执行
uv sync
```

## 三、使用

```bash
# 最常用：生成 xxx-clean.png（与原图同目录）
uv run celclean clean 你的图.png

# 指定输出文件名
uv run celclean clean 你的图.png -o 干净版.png

# 顺便输出测量报告（JSON，含前后对比的数字）
uv run celclean clean 你的图.png --report

# 生成前后对比图（整体一张 + 自动挑两个局部细节）
uv run celclean compare 你的图.png --out-dir 对比图

# 想自己指定要看哪几个局部：x,y,宽,高，可重复
uv run celclean compare 你的图.png --crop 860,150,200,200 --crop 280,640,180,180
```

批量处理（Windows 命令行）：

```bat
for %f in (*.png) do uv run celclean clean "%f"
```

## 四、参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--stride` | `2` | 窗口采样步长。**想更干净就把这个调成 1**：实测平坦像素局部起伏 0.0807 → **0.0548**、最坏改动只从 7.0 升到 8.0 色阶，代价是 0.9 s → 3.1 s |
| `--snap` / `--no-snap` | `--no-snap` | 把每个连通色块整体刷成**一个**颜色。色块会变得绝对纯净，但画面里较平缓的阴影会变成肉眼可见的台阶（见下文「为什么默认不开」） |
| `--snap-tol` | `0.5` | `--snap` 时判定「同一色块」的颜色容差（Lab 色差单位），越小越保守 |
| `--min-block` | `64` | 小于这个像素数的色块不重刷，交给去噪处理（保护小碎块细节） |
| `--radius` | 自动 | 去噪窗口半径。默认按图片大小自动算（1.25MP 图约 16 像素）。**噪声很轻的图用 `--radius 8~12` 更好**（实测 12→32 会掉约 1 dB） |
| `--strength 0.5~2` | `1.0` | 调低更保守。注意：**调高不会让色块更干净**——实测从 1.0 提到 3.0，平坦块没有任何改善，只是把最坏改动从 7.0 推到 21.3 色阶、>8 色阶的像素从 0 升到 1.29% |
| `--alpha keep` | `normalize` | `keep` = 不改 alpha（内部 253 保持 253）。`normalize` 会把内部 alpha 统一成 255，它改动的像素数**比去噪本身还多**（约 77% 的像素、各 1–2 色阶），但对"修掉 AI 出图的半透明脏 alpha"是必要的 |
| `--aa-band` | `2` | 每个色块边缘保留不重刷的宽度（保护抗锯齿）。注意：**只在 `--snap` 时生效**，关掉 snap 时改它输出逐字节相同 |

## 五、它到底是怎么做的

- **S0 只认 alpha 说了算**：AI 图的透明区域里 RGB 是垃圾数据（常见纯白、纯黑混着）。工具先按
  `alpha ≥ 24` 划出「真像素」，这些垃圾永远不会被平均进画面里。
- **S1 先量噪声**：用 3×3 拉普拉斯在「局部平坦」的像素上估出噪声强度，后面所有阈值都是它的倍数，
  不写死数字。
- **S2 保边去噪（核心）**：CIELab 空间里，把每个像素替换成「周围一圈颜色差得不超过约 1.5 色差单位的
  像素」的加权平均。
  - 颗粒和云雾 → 颜色相近，被平均掉（噪声 ÷ √n）；
  - 真正的边缘 → 对面颜色差太远，权重为 0，**边缘原样保留**；
  - 真正的渐变 → 线性渐变的局部平均还是它自己，**渐变原样保留**；
  - 细线/细笔画 → 线本身的像素互相平均，**笔画保留**；
  - 而且这个估计是**无偏的**（不会像某些滤波器那样把小块整体压暗几个色阶）。
- **S3 可选：色块整体重刷（`--snap`）**：找出「整片都平坦」的连通区域，用这块自己的平均色覆盖它。
  局部平均做不到的「比窗口还大的低频云雾」，这一步能彻底抹平——代价是缓坡阴影会变成台阶。
- **S4 alpha 收尾**：内部 alpha（250–254）统一成 255；背景里 α=1/2 的杂点归零；完全透明的像素 RGB 清零。

## 六、实测数据（针对仓库里的 `avator.png`，默认参数）

| 指标 | 数值 |
|---|---|
| 平坦色块的平均色偏差（选了 8 个最平的 32×32 窗口） | 最差 **0.12 色阶**（无偏，不会整块变亮/变暗） |
| 平坦色块的抖动（std） | 最平的窗口从 0.32–0.36 → **0.05–0.10**；含真实渐变的窗口保持 0.19–0.38（有意保留） |
| 局部细颗粒噪声强度 | 0.209 → **0.0** |
| 局部起伏（半径 9 中值残差，只在「本来平坦」的像素上统计） | 0.267 → **0.081（−70%）** |
| 与原始画面的亮度相关性 | **0.99993**（渐变、线条、结构都没被破坏） |
| 每个像素被改动的幅度（去噪域，α≥24） | 平均 0.61 色阶，99% 的像素 ≤ 3.7 色阶，**最大值 7.0 色阶** |
| 白底合成后全像素的最大改动（观众实际看到的） | **7.8 色阶**；>8 色阶的像素 **0 个** |
| 耗时 / 内存 | 1254×1254 **约 0.9–1.0 秒**、峰值内存 153 MB；4096×4096 **21.3 秒**（v1 是 210.5 秒，**8.4–9.9×**）、峰值内存 1.0 GB（v1 2.1 GB）。性能优化本身**不改动任何像素**：与优化前逐像素 max\|Δ\| = 0、PNG 字节相同（α≥24 掩码内两档尺寸都验证过）。v2 唯一有意的像素变化是半透明边缘 α<24 的 RGB，见 7.1 |

复现方式：`uv run celclean clean avator.png --report`，数字会写进 `avator-report.json`。

**为什么默认不开 `--snap`？** 它确实能把色块刷到绝对纯净（实测 8 个最平坦窗口里 **7 个 std 直接变
0.0**，剩下那个是真实渐变窗口，被保留）。但这张图的皮肤、头发有大片**真实缓坡阴影**，`--snap` 会把
它们刷成 1–2 色阶的台阶（脸颊渐变与原始画面的相关性从 0.997 掉到 0.96，肉眼能看出淡淡的分层；
逐像素最大改动也从 7.0 色阶升到 21.4 色阶）。所以默认只做去噪，`--snap` 留给真正需要的图。

## 七、独立验证：它到底改了什么，别人做得怎么样

### 7.1 用预训练视觉模型交叉验证（ViT-B/16 + ResNet-50，独立于本工具的实现）

- **浅层结构完好**：patch 特征余弦 **最低 0.9936 / 中位 0.9998**、CKA **0.99989** —— 纹理、边缘、笔画没被动。
- **深层语义布局完好**：196 个 patch 里 **193 个**依旧"最像自己"，唯一实质失配是帽子上高光周围的那片云雾（正是要抹掉的目标）。
- **量级校准**：纯去噪那部分的改动**比 JPEG q90 压缩还轻**（深层 CKA 0.9972 vs 0.9952）；但和"同幅度的随机噪声"相比更重（0.9926 vs 0.9996）——因为它是**成片**改的，噪声是逐点抵消的。
- **反例（v2 已修）**：半透明边缘（α<24）的像素原来会被写黑，在白底上变成 1166 个浅灰点（最暗 21.4 色阶），而旧指标把它排除在统计之外。v2 让这些像素保留原色：白底渲染下的最大改动 **21.4 → 7.8 色阶**、>8 色阶像素 **1166 → 0**（去噪部分逐像素未变）。验收报告现在同时给出"去噪域"和"白底合成全像素"两行数字。

### 7.2 和同类开源工具对比（调研 41 个候选，实测 19 种工具 / 34 个参数档）

| 做法 | 平坦块纯净度 | 真实渐变 | 1–2px 细线 | 最坏改动 | alpha | 依赖体积 |
|---|---|---|---|---|---|---|
| **celclean 默认** | std 0.227 | 保留（相关 0.9996） | 保留 | **max 7.0 色阶，>8 色阶 0 个** | 完整处理 | 57 MB |
| celclean `--stride 1` | 0.220（纯色占比 0.463） | 保留 | 保留 | max **8.0**，>8 色阶 0 个 | 同上 | 同上 |
| celclean `--snap` | **0.045**（7/8 窗口绝对纯色） | 保留 | 保留 | max 21.4 | 同上 | 同上 |
| vtracer（矢量化重画） | **0.000**（8/8 绝对纯色） | **压成色带**（202→94 级） | **约 90% 被抹掉** | max 190–200 | 重写约 130 万像素 | 4.7 MB |
| waifu2x（AI 动漫去噪/超分） | 0.36（**比原图还差**） | 最忠实 | 保留 | max 66 | 不变 | 39 MB |
| cv2 双边 d21 | 0.243 | 保留 | 尚可 | max 10.5 | 无 | 113 MB |
| cv2 NL-means h3 | 0.190（5/8 窗口） | 保留 | 保留 | max 33.2 | 无 | 113 MB |
| 深度学习去噪 DnCNN / FFDNet | 0.38 | 保留 | 保留 | max 9–10，但 **1031–2482 个像素改动 >8 色阶** | 无 | — |
| 调色板量化（pngquant/PIL） | 0.29–0.38 | 压成 22–95 级色带 | 会产生假边 | max 40–117 | 部分 | 1 MB |

三条要点：

1. **"绝对纯净色块"只有矢量化能做到**，但它不是清洗而是重画：平均改动 2.7–19.4 色阶、腮红渐变被压成色带、**细线像素被抹掉约 90%**、透明背景被重新描摹成实体形状。
2. **通用去噪器没有安全中间档**：按真实噪声尺度（0.2 色阶）调，它们几乎什么都不做（DnCNN 的平坦块 std 0.389→0.381）；调到能去掉云雾，就开始重画像素（NL-means h=6：2.1 万个像素改动 >8 色阶；引导滤波 r=16：42% 的像素被改、最大 180 色阶）。**我们同时是"真的洗了"和"最坏改动有界"的那一档。**
3. **最接近的对手是 `cv2.bilateralFilter(d=21,σ=10)`**：0.95 秒、平坦像素局部起伏 0.0445（我们同批次实测 0.0871 / 当前版本 0.0807）、纯色占比 0.462（我们 0.350）——它在"更干净"上赢，但**最坏改动 10.5 > 我们 7.0**，且不处理 alpha。用我们的 `--stride 1` 档对比它：最坏改动 **8.0** vs 10.5、纯色占比 **0.463** vs 0.462、色块偏移 **0.122** vs 0.159、平均改动 0.634 vs 0.632 —— **除速度外全面持平或更好**。

### 7.3 想更干净就用这三档（都实测过）

| 档位 | 命令 | 效果 | 代价（本机 1254²，优化后） |
|---|---|---|---|
| 默认 | `uv run celclean clean x.png` | 平坦起伏 0.081、纯色占比 0.350、max 7.0 色阶 | **0.9 s** |

## 八、常见问题

**合成到深色背景后感觉变亮了一点点？**
原图的内部 alpha 是 250–254（不是 255）。默认会统一成 255，合成到黑底上最多亮 5 个色阶（约 2% 的像素）。
在意的话用 `--alpha keep`。

**放大看渐变里有淡淡的横条（色带）？**
这是 8-bit 量化的固有现象，而且**去噪会把它显出来**：原图的颗粒噪声恰好充当了抖动，颗粒被去掉后，
渐变就还原成 1 色阶的台阶（实测这张图腮红区 ≥12px 的平台面积从 4.5% 涨到 56%）。这是"纯净"与
"无台阶"在 8-bit 输出下的取舍，我们选了纯净。缓解办法：`--radius 8` 更柔和；或导出后加轻抖动
（详细验证见项目内 `_probe/enhance/REPORT.md` 的 H1）。

**边缘上一两个像素的高对比白点/黑点没被清掉？**
这些点和「真实高光/细节」在数学上无法区分，工具选择保留（宁可留着，也不冒险擦掉真东西）。
实测这张图里这类"可疑点"有 91% 是贴在线稿/发丝交界处的**正常渲染像素**，强行清除会碰掉真实高光
（1/6 的误伤率），所以默认不动。用 PS 的污点修复画笔点两下更稳。

**为什么深色的地方感觉清洗得比较狠？**
阈值用的是 CIELab 色差，与人眼感受一致：暗部 1 个色阶 ≈ 0.3 色差单位，亮部 1 个色阶 ≈ 1 色差单位。
所以「同样肉眼可见的变化」在所有亮度下被同等对待。想要更保守就 `--strength 0.6`。

**支持哪些格式？** 任何 Pillow 能读的格式（PNG/JPG/WebP…），输出统一是 PNG（RGBA，保留透明）。

## 九、限制

- 它是给**平涂/赛璐璐**风格用的。厚涂、水彩、真实照片会被当成「大块噪声」抹掉细节，请用
  `--strength 0.4~0.6`，或者别用。
- 不做放大、不做补画、不做上色——只做「底色变干净」。
- `--snap` 的「同一色块」判定是颜色容差驱动的，容差过大会把本该分开的两级阴影并成一块，
  过小则色块刷不干净；默认值在同一张图上经过实测调过，换图请微调。
- **8-bit 输出下「绝对纯色块」与「看不到色带」在亚色阶区域数学上互斥**：真色值落在两个 8-bit
  色阶之间时，要么抖成两色（有颗粒、无台阶），要么取整成一个色（纯净、有台阶）。本工具默认选纯净；
  想反过来的话目前没有开关（EnhanceProto 的 H1 原型已验证可行，见 `_probe/enhance/REPORT.md`）。
- 半径的自动规则按图像尺寸缩放，是个**实测够用的代理**：单张图**测不准**噪声的相关长度
  （我们试了三种估计方法都不行，振幅越小越不准），所以没有实现"按测量噪声自动定半径"。
  噪声很轻的图记得手动用 `--radius 8~12`（见 `_probe/calib/REPORT.md`）。
